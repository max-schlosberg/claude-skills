## What this skill does

`~/Downloads` is a **temporary staging area only** — never a filing cabinet. This skill
walks every file currently in it, and for each one either:

1. **Moves it up** into an existing top-level folder in `~` that already matches its
   category (e.g. a PDF for a class goes into `~/School/<course>`, a resume file goes into
   `~/job-stuff`) — **renaming it along the way if the current filename is generic or
   unhelpful**, to match the naming conventions already used in that destination, or
2. **Deletes it** (moved to Trash, not `rm -rf`) because it's clearly junk — an installer
   already run, a duplicate, a stray temp/cache file, or
3. **Asks the user** when it's genuinely not clear which of the above applies.

The run is only done when `~/Downloads` is empty except for invisible files
(`.DS_Store`, `.localized`).

**Never invent new folders inside Downloads as a destination.** Sorting into
`Downloads/Resume/`, `Downloads/School/`, etc. and leaving them there does not count as
done — see [[downloads-is-staging-only]] if that memory exists. Files must land in their
real home elsewhere in `~`.

---

## Step 1 — Survey the destinations first

Before touching anything, look at what already exists so new files match existing
conventions instead of inventing new ones:

```bash
ls -la ~
```

Then look one level into anything that looks like a filing folder (e.g. `~/School`,
`~/job-stuff`, `~/Projects`, `~/Pictures`, `~/obsidian`, `~/coding-practice`, `~/random`) to
learn naming conventions — casing, abbreviation style, per-class subfolders, etc. Use
`find ~/<folder> -maxdepth 2` for this. Do not hardcode a list of folders here — the
user's home directory layout changes over time, so re-survey it every run.

---

## Step 2 — List everything in Downloads

```bash
ls -la ~/Downloads
```

Ignore `.DS_Store` and `.localized` — they stay. Everything else needs a decision.

For anything whose purpose isn't obvious from the filename, `Read` it (or, for images,
just note the filename/size/dimensions) before deciding.

---

## Step 3 — Classify each file

Work through the list and bucket every file into one of these:

| Bucket | Signal | Action |
|---|---|---|
| **Obvious match to an existing folder** | Filename/content clearly matches a category already in `~` (course code matches an existing `~/School/<course>`, résumé/cover-letter matches `~/job-stuff`, a project zip matches something in `~/Projects`, a personal photo matches `~/Pictures`) | Move it there directly, no need to ask |
| **Obvious junk** | Installer (`.dmg`, `.pkg`) with a corresponding app already in `/Applications`, an exact duplicate of another file already handled (same name + `(1)`/copy suffix, same size), a stray partial/temp download (`.crdownload`, `.part`, `~$*`) | Delete (send to Trash) without asking |
| **New category, but confident** | Doesn't match an existing folder, but it's unambiguous what it is and where a sensible new top-level folder would go (e.g. first file for a brand-new class) | Create the new top-level folder (matching existing naming conventions) and move it, then mention this choice in the final summary |
| **Ambiguous** | Could go to more than one place, could be either a keeper or junk, purpose is unclear, or it's a personal/sensitive file (photo, PDF with personal info) where guessing wrong is costly | **Ask, don't guess** — see Step 4 |

Common ambiguous cases worth specifically watching for:
- **Duplicate-looking files** (`Lab_01.ipynb` vs `Lab_01(1).ipynb`, `flightdeck.jpg` vs a
  same-size extensionless `flight deck`) — ask which one to keep, or confirm they're
  identical before deleting one.
- **Photos with no obvious project/album match** — ask whether they're personal photos
  (→ `~/Pictures`, maybe a new dated subfolder) or disposable (meme, screenshot, wallpaper
  someone sent) before deleting anyone's photos.
- **Screenshots** — often disposable, but could be something the user still needs; ask if
  unsure rather than assuming they're junk.
- **Course material that doesn't obviously match an existing `~/School/<course>` folder** —
  don't guess the course; ask.

---

## Step 3.5 — Rename generic filenames before moving

For every file headed to a **Move** destination, check whether its filename is generic or
unhelpful. If so, rename it as part of the move — but don't rename gratuitously.

**Rename when the filename is:**
- Auto-generated by a camera, phone, or screenshot tool (`IMG_1234.HEIC`,
  `Screen Shot 2026-09-11 at 3.42.11 PM.png`, `Screenshot_20260911-154211.jpg`)
- A browser's collision-avoidance suffix or generic download name (`document(3).pdf`,
  `Untitled.pdf`, `download.zip`, `image (1).jpeg`)
- Uninformative relative to its content (e.g. content makes clear it's Lecture 4 notes for
  a specific class, but the file is named `notes.pdf`)

**Don't rename when:**
- The filename is already descriptive (`Lab_01.ipynb`, `2026_Resume_Schlosberg.pdf`)
- The destination has a required/expected filename format (e.g. an assignment submission
  the course expects named a specific way) — preserve it exactly
- Renaming would destroy information you can't recover elsewhere (a unique ID, a version
  number that matters) — when unsure, ask instead of guessing (Step 4)

**Pick the new name by matching the destination folder's existing convention** from the
Step 1 survey (casing, separators, date format, prefix/suffix style). If the destination
has no files yet or no clear convention, pick a short, descriptive name based on the file's
actual content (Read it first if the current name doesn't already tell you). Keep the
original extension.

If a good new name isn't obvious even after reading the file, leave the original filename
alone rather than guessing — a wrong file location is worse to fix than a generic name.

---

## Step 4 — Ask about anything unclear

Batch ambiguous files into `AskUserQuestion` calls (up to 4 questions per call, each with
a few concrete options plus the user's free-text "Other"). Prefer options phrased as
concrete actions, e.g.:

- "Move to `~/Pictures`"
- "Move to `~/School/stat134`"
- "Delete"
- "Keep both / not sure — leave it for now"

Group related files into one question with `multiSelect: true` when they clearly share
the same fate (e.g. "Which of these roller coaster photos should go to `~/Pictures`?").
Don't ask one question per file if several files share the same obvious question — batch
them.

Never delete anything the user hasn't confirmed unless it falls under "obvious junk" in
Step 3.

---

## Step 5 — Execute

For each decision made (auto-classified or answered by the user):

- **Move (no rename)**: `mv ~/Downloads/"<file>" ~/<destination>/`
- **Move with rename**: `mv ~/Downloads/"<file>" ~/<destination>/"<new-name>.<ext>"` — do the
  move and rename in one command rather than renaming in place first.
- **Delete**: send to Trash rather than `rm`, e.g. `mv ~/Downloads/"<file>" ~/.Trash/`
- Create any new destination folder first with `mkdir -p` if it doesn't exist yet.

Do this file-by-file rather than a single blind bulk command, since destinations differ
per file.

---

## Step 6 — Verify Downloads is empty

```bash
ls -la ~/Downloads
```

Should show only `.` `..` `.DS_Store` `.localized`. If anything remains (e.g. the user
said "leave it for now" to something), that's fine — just call it out explicitly in the
summary rather than silently leaving it.

---

## Step 7 — Report a summary

```
Downloads sort — YYYY-MM-DD

Moved:
  - <file> → ~/<destination>/
  - <file> → ~/<destination>/<new-name> (renamed)

Deleted (Trash):
  - <file> — <reason>

New folders created:
  - ~/<new-folder> (for <reason>)

Left in Downloads (user deferred):
  - <file> — <why>
```

Keep it short — a flat list, not prose.
